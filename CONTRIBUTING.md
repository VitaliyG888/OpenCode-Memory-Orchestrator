# Contributing

Thanks for considering a contribution.

1. Open an issue for substantial changes before starting implementation.
2. Keep Memory Intelligence as the single owner of the SQLite database and retrieval pipeline.
3. Keep the Orchestrator dependent on the public Core API; do not add a second database or vector index.
4. Add or update smoke tests for behavior changes.
5. Never include API keys, private transcripts, or local databases in pull requests.
6. Preserve provenance and non-destructive memory history.
7. Describe user-visible changes in `CHANGELOG.md`.

By intentionally submitting a contribution for inclusion, you agree that it is provided under Apache-2.0 unless a separate written agreement says otherwise.
